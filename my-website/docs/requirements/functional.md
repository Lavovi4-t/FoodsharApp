# Функциональные требования

## Юзкейсы

<details>
<summary><b>UC-01: Регистрация в приложении по номеру телефона</b></summary>

**Описание:** Процесс регистрации нового пользователя в приложении с использованием номера телефона и SMS-подтверждения.

**Акторы:** Незарегистрированный пользователь

**Основная функция:** Создание новой учетной записи пользователя с верификацией номера телефона через SMS.

---

### Детальное описание

| Раздел | Описание |
|--------|----------|
| ID | UC-01 |
| Название | Регистрация в приложении по номеру телефона |
| Акторы | Незарегистрированный пользователь |
| Предусловия | 1. Пользователь скачал и установил приложение; 2. Пользователь открыл приложение впервые; 3. Устройство имеет доступ к интернету и возможность приёма СМС |
| Постусловия (успех) | 1. Создана новая учетная запись пользователя; 2. Профиль пользователя заполнен минимальными данными (имя, телефон); 3. Пользователь авторизован в системе и перенаправлен на главный экран; 4. В системе зафиксированы дата и время регистрации |
| Постусловия (неудача) | 1. Учетная запись не создана; 2. Пользователь остается на экране входа/регистрации; 3. Система не сохраняет никаких данных пользователя |

### Основной поток

1. Система отображает экран приветствия с предложением войти или зарегистрироваться
2. Пользователь нажимает кнопку "Зарегистрироваться"
3. Система запрашивает номер мобильного телефона
4. Пользователь вводит номер телефона в международном формате (например, +375 33 385 81 20)
5. Пользователь нажимает кнопку "Получить код"
6. Система проверяет корректность формата номера
7. Система отправляет СМС с 6-значным кодом подтверждения на указанный номер
8. Система отображает экран ввода кода и запускает таймер на 60 секунд для возможности запросить код повторно
9. Пользователь вводит полученный 6-значный код подтверждения
10. Система проверяет соответствие введенного кода отправленному
11. Система создает новую учетную запись с уникальным идентификатором
12. Система запрашивает минимальные данные для заполнения профиля: Имя (обязательно, минимум 2 символа) и Согласие на обработку персональных данных (обязательно)
13. Пользователь заполняет имя и устанавливает согласие на обработку
14. Пользователь нажимает кнопку "Завершить регистрацию"
15. Система сохраняет данные профиля
16. Система автоматически авторизует пользователя
17. Система отображает главный экран приложения с приветственным сообщением

### Альтернативные потоки

**Альтернативный поток 1: Пользователь уже существует**

- *Точка входа:* во время пункта 5 основного потока
- 1. После ввода номера телефона система обнаруживает, что пользователь с таким номером уже зарегистрирован
- 2. Система отображает сообщение: "Пользователь с таким номером уже существует. Войти в существующий аккаунт?"
- 3. Пользователь выбирает "Войти"
- 4. Система переводит пользователя на экран ввода кода для авторизации (аналогично пункту 8 основного потока)
- 5. Продолжение с пункта 9 основного потока

**Альтернативный поток 2: Неверный формат номера**

- *Точка входа:* во время пункта 4 основного потока
- 1. После ввода номера система определяет, что номер введен в неверном формате
- 2. Система подсвечивает поле ввода красным и отображает сообщение: "Введите номер в формате +375 33 385 81 20"
- 3. Пользователь исправляет номер
- 4. Возврат к пункту 5 основного потока

**Альтернативный поток 3: Неверный код подтверждения**

- *Точка входа:* во время пункта 10 основного потока
- 1. После ввода кода система определяет, что код неверен
- 2. Система отображает сообщение об ошибке: "Неверный код. Попробуйте снова"
- 3. Поле ввода кода очищается
- 4. Счетчик попыток увеличивается на 1
- 5. Пользователь может ввести код повторно (до 3 попыток)

**Альтернативный поток 4: Повторная отправка кода**

- *Точка входа:* во время пункта 8 основного потока
- 1. Пользователь не получил СМС или код истек
- 2. Пользователь нажимает кнопку "Отправить код повторно" после истечения таймера 60 секунд
- 3. Система отправляет новый СМС-код на указанный номер
- 4. Таймер сбрасывается и запускается заново
- 5. Возврат к пункту 9 основного потока

**Альтернативный поток 5: Отказ от согласия на обработку данных**

- *Точка входа:* во время пункта 12 основного потока
- 1. На шаге заполнения профиля пользователь не устанавливает согласие на обработку данных
- 2. Кнопка "Завершить регистрацию" неактивна
- 3. Система отображает подсказку: "Необходимо согласие на обработку персональных данных для продолжения"
- 4. Пользователь устанавливает согласие
- 5. Кнопка становится активной
- 6. Возврат к пункту 14 основного потока

### Исключительные потоки

**Исключительный поток 1: Превышение лимита попыток ввода кода**

- *Точка входа:* во время альтернативного потока 3
- 1. Пользователь ввел неверный код 3 раза подряд
- 2. Система блокирует возможность ввода кода для этого номера на 15 минут
- 3. Система отображает сообщение: "Превышено количество попыток. Повторите через 15 минут"
- 4. Регистрация прерывается

**Исключительный поток 2: Ошибка отправки СМС**

- *Точка входа:* во время пункта 7 основного потока
- 1. При попытке отправки СМС происходит сбой в работе отправки СМС
- 2. Система не получает подтверждения об отправке сообщения
- 3. Система отображает сообщение: "Ошибка отправки кода. Попробуйте позже или используйте другой способ регистрации"
- 4. Пользователь может повторить попытку через кнопку "Повторить" или вернуться назад

**Исключительный поток 3: Потеря интернета**

- *Точка входа:* во время любого пункта
- 1. В процессе регистрации пропадает интернет-соединение
- 2. Система отображает экран: "Отсутствует подключение к интернету. Проверьте сеть"
- 3. Все действия блокируются до восстановления соединения
- 4. При восстановлении соединения система возвращается к текущему шагу

### Бизнес правила

| ID | Правило |
|----|---------|
| BR-01 | Номер телефона является уникальным идентификатором пользователя в системе |
| BR-02 | Срок действия СМС-кода - 5 минут |
| BR-03 | Максимальное количество попыток ввода кода - 3, после чего требуется повторная отправка или блокировка на 15 минут |
| BR-04 | Минимальная длина имени - 2 символа, максимальная - 50 символов |

<summary><b>UC-02: Создание и публикация объявления о доступной еде</b></summary>

**Описание:** Процесс создания и публикации объявления о еде, которую пользователь хочет отдать бесплатно.

**Акторы:** Зарегистрированный пользователь

**Основная функция:** Создание нового объявления с фотографиями, описанием продукта, указанием места и времени выдачи.

---

### Детальное описание

| Раздел | Описание |
|--------|----------|
| ID | UC-02 |
| Название | Создание и публикация объявления о доступной еде |
| Акторы | Зарегистрированный пользователь |
| Предусловия | 1. Пользователь авторизован в приложении; 2. Пользователь имеет при себе еду, которую хочет отдать, или доступ к ее фото; 3. Устройство имеет доступ к камере или галерее фотографий |
| Постусловия (успех) | 1. Новое объявление создано со статусом "Активно"; 2. Объявление видно в общей ленте и на карте для всех пользователей; 3. Пользователь может просматривать и управлять объявлением в разделе "Мои объявления"; 4. Счетчик активных объявлений пользователя увеличивается на 1 |
| Постусловие (неудача) | 1. Объявление не создано; 2. Данные, введенные пользователем, не сохраняются; 3. Пользователь возвращается к экрану создания объявления или на главный экран |

### Основной поток

1. Пользователь на главном экране нажимает кнопку "+" (или "Добавить еду")
2. Система проверяет, не превышен ли лимит активных объявлений для данного пользователя
3. Система открывает экран создания объявления с пустой формой
4. Система автоматически запрашивает разрешение на доступ к камере и геолокации (если ранее не было разрешений)
5. Пользователь нажимает кнопку "Добавить фото"
6. Система открывает выбор источника: камера или галерея
7. Пользователь выбирает камеру и делает снимок еды (или выбирает фото из галереи)
8. Система отображает превью загруженного фото
9. Пользователь при необходимости добавляет еще фото (до 3 снимков)
10. Пользователь заполняет обязательные поля формы:
    - Название продукта (текстовое поле, например "Свежие овощи", "Хлеб", "Готовая еда")
    - Категория (выбор из выпадающего списка: Выпечка, Овощи/фрукты, Готовые блюда, Бакалея, Напитки, Другое)
    - Вес/количество (числовое поле с выбором единиц: кг, л, шт.)
    - Срок годности (выбор даты из календаря, не ранее сегодняшнего дня)
11. Пользователь заполняет опциональные поля:
    - Описание (текстовое поле, например "Вкусный домашний пирог, разрезан на кусочки")
    - Место передачи: система автоматически подставляет текущий адрес по геолокации (если разрешение получено); пользователь может скорректировать адрес или поставить метку на карте вручную
    - Время для забора: переключатель "Доступно сейчас" (активирован по умолчанию) или выбор временного интервала (например, "с 18:00 до 21:00")
12. Пользователь нажимает кнопку "Опубликовать"
13. Система выполняет валидацию всех заполненных полей
14. Система сохраняет объявление в базе данных со статусом "Активно"
15. Система отображает сообщение об успехе: "Объявление опубликовано!"
16. Система перенаправляет пользователя в раздел "Мои объявления", где новое объявление отображается первым в списке

### Альтернативные потоки

**Альтернативный поток 1: Превышен лимит активных объявлений**

- *Точка входа:* во время пункта 2 основного потока
- 1. Система определяет, что у пользователя уже есть 5 активных объявлений (максимум)
- 2. Система отображает сообщение: "У вас уже 5 активных объявлений. Завершите или закройте одно из них, чтобы создать новое"
- 3. Система предлагает перейти в раздел "Мои объявления" для управления
- 4. Создание нового объявления блокируется

**Альтернативный поток 2: Добавление нескольких фото**

- *Точка входа:* во время пункта 8 основного потока
- 1. После добавления первого фото пользователь нажимает "Добавить еще"
- 2. Система повторно открывает выбор источника (камера/галерея)
- 3. Пользователь добавляет дополнительные фото
- 4. Система отображает миниатюры всех загруженных фото
- 5. Пользователь может удалить любое фото, нажав на крестик
- 6. Возврат к пункту 10 основного потока

**Альтернативный поток 3: Отказ от геолокации**

- *Точка входа:* во время пункта 11 основного потока
- 1. При запросе геолокации пользователь запрещает доступ к местоположению
- 2. Система скрывает автоматическое определение и отображает поля для ручного ввода адреса
- 3. Пользователь вводит адрес вручную (город, улица, дом)
- 4. Система проверяет корректность адреса
- 5. Возврат к пункту 11 основного потока

**Альтернативный поток 4: Редактирование перед публикацией**

- 1. На этапе предпросмотра (после заполнения) пользователь замечает ошибку
- 2. Пользователь нажимает кнопку "Редактировать"
- 3. Система возвращает на экран редактирования с уже заполненными полями
- 4. Пользователь вносит изменения
- 5. Возврат к пункту 14 основного потока (повторная публикация)

### Исключительные потоки

**Исключительный поток 1: Ошибка валидации полей**

- *Точка входа:* во время пункта 13 основного потока
- 1. При попытке публикации система обнаруживает, что обязательные поля не заполнены или заполнены некорректно
- 2. Система подсвечивает красным поля с ошибками и отображает сообщения: "Добавьте хотя бы одно фото", "Укажите название продукта", "Укажите срок годности", "Укажите адрес"
- 3. Публикация блокируется до исправления ошибок
- 4. Пользователь исправляет ошибки
- 5. Возврат к пункту 14 основного потока

**Исключительный поток 2: Ошибка загрузки фото**

- *Точка входа:* во время пунктов 7 и 9 основного потока
- 1. При загрузке фото происходит ошибка (недостаточно памяти, обрыв соединения)
- 2. Система отображает сообщение: "Не удалось загрузить фото. Попробуйте еще раз или выберите другое"
- 3. Пользователь может повторить загрузку или пропустить (если есть другие фото)

**Исключительный поток 3: Потеря интернета при публикации**

- *Точка входа:* во время пункта 12 основного потока
- 1. Пользователь нажал "Опубликовать", но в момент отправки данных пропало соединение
- 2. Система сохраняет объявление локально на устройстве
- 3. Система отображает сообщение: "Отсутствует интернет. Объявление будет опубликовано автоматически при восстановлении соединения"
- 4. Объявление помечается как "Ожидает публикации" в разделе "Мои объявления"
- 5. При восстановлении интернета система автоматически публикует объявление и отправляет уведомление пользователю

**Исключительный поток 4: Ошибка сервера**

- *Точка входа:* во время пункта 12 основного потока
- 1. При сохранении объявления сервер возвращает ошибку (500 Internal Server Error)
- 2. Система отображает сообщение: "Техническая ошибка. Мы уже работаем над ее устранением. Попробуйте позже"
- 3. Пользователю предлагается сохранить объявление локально
- 4. Инцидент логируется для команды разработки

### Бизнес правила

| ID | Правило |
|----|---------|
| BR-01 | Минимальное количество фотографий для публикации - 1 |
| BR-02 | Максимальное количество фотографий - 3 |
| BR-03 | Максимальное количество активных объявлений от одного пользователя - 5 |
| BR-04 | Срок годности не может быть раньше текущей даты (допускается сегодняшняя дата) |
| BR-05 | Запрещена публикация продуктов любого происхождения без указания срока годности |
| BR-06 | Объявления автоматически деактивируются после истечения срока годности |

<details>
<summary><b>UC-03: Проверка и модерация объявлений службой поддержки</b></summary>

**Описание:** Процесс проверки и модерации объявлений сотрудником службы поддержки для обеспечения соответствия правилам платформы.

**Акторы:** Модератор (служба поддержки)

**Основная функция:** Проверка новых объявлений и объявлений, поступивших по жалобам, с возможностью одобрения, отклонения или блокировки пользователя.

---

### Детальное описание

| Раздел | Описание |
|--------|----------|
| ID | UC-03 |
| Название | Проверка и модерация объявлений службой поддержки |
| Акторы | Модератор (служба поддержки) |
| Предусловия | 1. Модератор авторизован в системе с правами модератора; 2. В системе есть объявления, требующие модерации (новые или по жалобам); 3. Модератор открыл административную панель |
| Постусловия (успех) | 1. Объявление одобрено и опубликовано; 2. Пользователь получил уведомление; 3. Объявление видно всем пользователям |
| Постусловия (неудача) | 1. Объявление отклонено; 2. Пользователь уведомлен о причине отказа; 3. Объявление не попадает в общий доступ |

### Основной поток

1. Модератор открывает раздел "Модерация объявлений" в админ-панели
2. Система отображает список объявлений, ожидающих проверки, с сортировкой по дате (самые новые сверху)
3. Для каждого объявления система отображает:
   - Фото продукта
   - Текст объявления (название, описание, категория, срок годности)
   - Данные донора (имя, рейтинг, история предыдущих публикаций)
   - Кнопки действий: "Одобрить", "Отклонить", "Заблокировать пользователя"
4. Модератор открывает первое объявление из списка для детального просмотра
5. Модератор проверяет объявление на соответствие правилам:
   - Фото соответствует описанию
   - Продукт выглядит пригодным для употребления
   - Срок годности указан корректно
   - Нет признаков мошенничества или запрещенных товаров (алкоголь, табак)
6. Модератор нажимает кнопку "Одобрить"
7. Система меняет статус объявления на "Активно" (становится доступно в ленте и на карте)
8. Система отправляет push-уведомление донору: "Ваше объявление опубликовано!"
9. Модератор переходит к следующему объявлению

### Альтернативные потоки

**Альтернативный поток 1: Отклонение объявления**

- *Точка входа:* во время пункта 5 основного потока
- 1. Модератор обнаруживает нарушение (некорректное фото, просроченный продукт, запрещенная категория)
- 2. Модератор нажимает кнопку "Отклонить"
- 3. Система открывает окно с выбором причины отклонения:
   - "Фото не соответствует описанию"
   - "Продукт выглядит испорченным"
   - "Указан просроченный срок годности"
   - "Запрещенная категория (алкоголь/табак)"
   - "Другое" (с текстовым полем)
- 4. Модератор выбирает причину (или вводит свою)
- 5. Система сохраняет решение и меняет статус объявления на "Отклонено"
- 6. Система отправляет push-уведомление пользователю с указанием причины отказа
- 7. Возврат к пункту 2 основного потока

**Альтернативный поток 2: Блокировка пользователя**

- *Точка входа:* во время пункта 5 основного потока
- 1. При проверке объявления модератор видит, что пользователь систематически нарушает правила (много жалоб, неоднократные отклонения)
- 2. Модератор нажимает кнопку "Заблокировать пользователя"
- 3. Система запрашивает подтверждение и причину блокировки
- 4. Модератор подтверждает блокировку
- 5. Система блокирует пользователя (все его объявления скрываются, новые создавать нельзя)
- 6. Система отправляет уведомление пользователю о блокировке с указанием причины
- 7. Возврат к пункту 2 основного потока

**Альтернативный поток 3: Модерация по жалобе**

- *Точка входа:* во время пункта 1 основного потока
- 1. Модератор открывает раздел "Жалобы" в админ-панели
- 2. Система отображает список жалоб от пользователей (с указанием причины и ссылкой на объявление)
- 3. Модератор открывает жалобу и просматривает спорное объявление
- 4. Модератор принимает решение:
   - Если жалоба обоснована — отклоняет объявление или блокирует пользователя
   - Если жалоба необоснованна — оставляет объявление активным и помечает жалобу как "рассмотрена, отказано"
- 5. Система уведомляет пользователя, подавшего жалобу, о результате рассмотрения

### Исключительные потоки

**Исключительный поток 1: Ошибка при сохранении решения**

- *Точка входа:* во время пункта 6 основного потока
- 1. Модератор принял решение, но при сохранении произошла ошибка сервера
- 2. Система отображает сообщение: "Ошибка сохранения. Попробуйте еще раз"
- 3. Решение не применяется, модератор может повторить попытку

**Исключительный поток 2: Конфликт одновременной модерации**

- *Точка входа:* во время пункта 4 основного потока
- 1. Два модератора одновременно пытаются модерировать одно и то же объявление
- 2. Система блокирует объявление для второго модератора с сообщением: "Объявление уже модерируется другим модератором"

<summary><b>UC-05: Бронирование еды и коммуникация пользователей через встроенный чат</b></summary>

**Описание:** Процесс бронирования еды из объявления и последующая коммуникация между пользователями через встроенный чат для согласования деталей передачи.

### Детальное описание

| Раздел | Описание |
|--------|----------|
| ID | UC-05 |

| Акторы | Зарегистрированные пользователи |
| Предусловия | 1. Пользователь нашел интересующее объявление (через UC-04); 2. Объявление имеет статус "Активно" и не забронировано другим пользователем; 3. Оба пользователя авторизованы в системе; 4. Устройства имеют доступ к интернету |

1. Пользователь открывает детальную карточку объявления (нажимает на метку на карте или элемент в ленте)
2. Система отображает полную информацию об объявлении, включая рейтинг пользователя
3. Пользователь нажимает кнопку "Хочу забрать"
4. Система проверяет статус объявления в реальном времени
5. Система создает заявку на получение и мгновенно изменяет статус объявления на "Забронировано"
6. Объявление становится невидимым для других пользователей (пропадает из общего поиска)
7. Система автоматически создает новый чат между пользователями
8. Система отправляет push-уведомление донору:
   - Заголовок: "Новая заявка!"
   - Текст: "Пользователь [Имя] хочет забрать вашу еду: [Название]. Перейдите в чат для подтверждения"
9. Донор открывает уведомление и попадает в созданный чат
10. Система отображает в чате системное сообщение: "Заявка создана. Договоритесь о деталях встречи"
11. Стороны обсуждают детали передачи (точное время, место встречи, ориентиры)
12. После успешной встречи и получения еды получатель нажимает кнопку "Я получил еду" (кнопка появляется в чате через 1 час после брони)

14. Система отправляет уведомление донору: "Пользователь [Имя] подтвердил получение еды"

- 5. Система уведомляет получателя об отказе с указанием причины
- 6. Система меняет статус объявления:
   - Если причина "Еда испортилась" или "Еду уже отдали" — статус "Закрыто"
   - Если причина "Передумал" — статус "Активно" (если еда еще есть)
- 7. Система отправляет уведомление получателю

**Альтернативный поток 3: Отказ пользователя-получателя**

- 2. Получатель в чате нажимает кнопку "Отменить бронь"

<summary><b>UC-06: Оценка пользователя и оставление отзыва после завершения сделки</b></summary>

**Описание:** Процесс оценивания друг друга и оставления текстовых отзывов после завершения сделки по передаче еды.

**Акторы:** Зарегистрированные пользователи

**Основная функция:** Выставление оценки по шкале от 1 до 5 звезд, написание текстового отзыва, пересчет общего рейтинга пользователя.

---

### Детальное описание

| Раздел | Описание |
|--------|----------|
| ID | UC-06 |
| Название | Оценка пользователя и оставление отзыва после завершения сделки |
| Акторы | Зарегистрированные пользователи |
| Предусловия | 1. Сделка завершена (статус объявления "Завершено"); 2. Пользователи еще не оценили друг друга в рамках этой конкретной сделки; 3. Оба пользователя авторизованы в системе |
| Постусловия (успех) | 1. Оценки и отзывы сохранены в системе; 2. Общий рейтинг пользователей пересчитан и обновлен; 3. Отзывы видны в профилях пользователей при просмотре другими |
| Постусловия (неудача) | 1. Оценка не сохранена; 2. Пользователь может вернуться к оценке позже (до 7 дней) |

### Основной поток

1. После подтверждения получения еды система автоматически открывает экран оценки пользователя
2. Система отображает:
   - Фото и имя пользователя (если фото нет — аватар по умолчанию)
   - Название полученного продукта
   - Заголовок: "Как прошла сделка?"
   - 5 звезд для оценки
   - Поле для текстового отзыва
   - Кнопка "Пропустить" (внизу слева)
   - Кнопка "Отправить оценку" (внизу справа, неактивна пока не выставлены звезды)
3. Пользователь нажимает на звезды для выставления оценки (например, 4 звезды из 5)
4. Кнопка "Отправить оценку" становится активной
5. Пользователь может написать текстовый отзыв
6. Пользователь нажимает кнопку "Отправить оценку"
7. Система сохраняет оценку и отзыв, привязывая их к пользователю и к данной сделке
8. Система пересчитывает общий рейтинг пользователя (среднее арифметическое всех полученных оценок)
9. Система отображает сообщение: "Спасибо за отзыв!"
10. Система перенаправляет пользователя на главный экран или в профиль
11. Система отправляет push-уведомление другому пользователю: "Вам оставили отзыв! Посмотрите в профиле"

### Альтернативные потоки

**Альтернативный поток 1: Пропуск оценки (оценить позже)**

- *Точка входа:* во время пункта 2 основного потока
- 1. На экране оценки пользователь нажимает кнопку "Пропустить" или "Оценить позже"
- 2. Система закрывает экран оценки без сохранения
- 3. В течение следующих 7 дней система будет периодически (не чаще 1 раза в день) напоминать о возможности оценить через push-уведомления
- 4. Через 7 дней возможность оценки для этой конкретной сделки блокируется

**Альтернативный поток 2: Редактирование отзыва**

- *Точка входа:* во время пункта 10 основного потока
- 1. Пользователь хочет изменить уже оставленный отзыв
- 2. Пользователь переходит в свой профиль, раздел "Мои отзывы" (или "Мои оценки")
- 3. Находит нужный отзыв и нажимает кнопку "Редактировать"
- 4. Система открывает экран редактирования, где:
   - Оценку (звезды) изменить нельзя (только через обращение в поддержку)
   - Текст отзыва можно редактировать
- 5. Пользователь изменяет текст отзыва
- 6. Нажимает "Сохранить"
- 7. Система обновляет отзыв с пометкой "отредактировано" и датой редактирования

**Альтернативный поток 3: Оценка без текстового отзыва**

- *Точка входа:* во время пункта 3 основного потока
- 1. На экране оценки пользователь выставляет звезды
- 2. Пользователь оставляет поле текстового отзыва пустым
- 3. Нажимает "Отправить оценку"
- 4. Система сохраняет только числовую оценку
- 5. В профиле отображается только оценка звездами без текста

**Альтернативный поток 4: Жалоба на отзыв**

- *Точка входа:* во время пункта 10 основного потока
- 1. Пользователь видит в своем профиле негативный отзыв, который считает несправедливым или оскорбительным
- 2. Пользователь нажимает кнопку "Пожаловаться" на этом отзыве
- 3. Система открывает форму жалобы с выбором причины:
   - Оскорбления или нецензурная лексика
   - Ложная информация
   - Спам
   - Другое (с текстовым полем)
- 4. Пользователь выбирает причину и отправляет жалобу
- 5. Жалоба направляется на модерацию
- 6. Модератор рассматривает жалобу
- 7. При подтверждении нарушения отзыв скрывается, пользователю выносится предупреждение

### Исключительные потоки

**Исключительный поток 1: Низкий рейтинг вызывает блокировку**

- *Точка входа:* во время пункта 8 основного потока
- 1. После обновления рейтинга система проверяет, не опустился ли средний рейтинг пользователя ниже 2 звезд (при минимум 5 оценках)
- 2. Если рейтинг ниже 2 звезд, система:
   - Отправляет уведомление пользователю: "Ваш рейтинг опустился ниже 2. Это может привести к блокировке"
   - Блокирует возможность создавать новые объявления или бронировать
   - Предлагает связаться с поддержкой для разблокировки

**Исключительный поток 2: Ошибка сохранения оценки**

- *Точка входа:* во время пункта 7 основного потока
- 1. При попытке сохранить оценку происходит ошибка сервера
- 2. Система отображает сообщение: "Не удалось сохранить оценку. Попробуйте позже"
- 3. Оценка сохраняется локально и повторяется попытка отправки при восстановлении соединения

### Бизнес правила

| ID | Правило |
|----|---------|
| BR-01 | Оценки анонимны для других пользователей (видят только средний рейтинг, не видят, кто и как оценил) |
| BR-02 | Отзывы публичны и отображаются с именем автора, датой и пометкой "отредактировано" (если было) |
| BR-03 | Нельзя оценить самого себя |
| BR-04 | Средний рейтинг рассчитывается как среднее арифметическое всех оценок за последние 12 месяцев |
| BR-05 | Минимальное количество оценок для отображения рейтинга - 3 (иначе отображается "Новый пользователь") |
| BR-06 | За необоснованные жалобы на отзывы пользователь может быть заблокирован |
